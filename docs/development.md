# 开发指南

## 阶段计划

1. 项目骨架、工具链配置与本地构建检查。
2. MySQL 表结构、索引、初始化数据与安全升级脚本。
3. SSM 配置、统一响应/异常、参数校验、JWT 与密码摘要。
4. 分类、商品、规格、加料与库存。
5. 用户首页、菜单、商品选择、购物车与门店。
6. 创建订单、服务端计价、库存事务与订单状态流转。
7. 用户账户、优惠券、积分与订单历史。
8. 管理员认证与管理模块。
9. 提供真实服务商与凭据后再接入支付。
10. 安全与端到端测试。
11. 部署与运维文档。

## 当前进度

第二阶段：规范数据库包含 25 张 `dc_` 前缀表，使用 DECIMAL 金额字段和逻辑删除，脚本不会删除表。当前工作区没有配置 MySQL 客户端/服务，因此尚未实际执行脚本。

第三阶段：已完成 Spring MVC、MyBatis、数据源与事务配置、校验、统一响应与异常、请求标识、JWT、BCrypt，以及用户/管理员拦截器。

第四阶段：已实现公开分类/商品查询、商品详情中的规格和加料读取、管理员商品新增编辑与上下架、事务库存调整及库存审计记录。用户端首页会请求真实 API，并显示加载、错误和空状态。管理员现可在分类管理页新增、编辑、排序和启停分类；停用分类会将其商品从用户菜单隐藏，不物理删除分类或商品。没有伪造商品种子数据。

第八阶段当前切片：已实现管理员账号密码登录 API 和管理端登录页；登录令牌由管理端请求拦截器附加到受保护 API。商品管理页支持真实商品查询、新增、编辑、上下架与库存调整；分类管理页支持真实分类新增、编辑、排序和启停。数据库种子脚本不创建管理员；需先在 `dc_admin` 中安全配置账号及 BCrypt 密码摘要。

第五阶段进行中：用户端 H5 和管理端的 `/api` 开发代理已分别接入 IntelliJ IDEA 当前的 Tomcat 应用上下文，并在本机实测分类接口均返回 HTTP 200。用户端商品卡片现可打开真实商品详情，显示后端返回的规格、加料与动态价格，并校验规格必选项和加料库存；管理端商品目录现支持维护规格组、规格值和加料，保存时使用事务和逻辑停用旧配置。购物车及门店流程尚未完成；购物车需接后端和用户身份，不用本地假数据冒充已持久化购物车。

第七阶段准备切片：已实现用户手机号/密码注册与登录、BCrypt 密码摘要、USER 角色 JWT、用户端账户页、令牌本地保存及请求自动附加。当前没有短信服务商，注册未验证手机号，仅用于本机开发验证；正式开放注册前必须接入手机号验证及防滥用策略。购物车尚未接入。

第五阶段新增切片：已实现门店列表、门店选择、按用户与门店持久化的购物车 API 与用户端购物车页。加入购物车由服务端校验在售商品、规格选择、加料有效性并计算单价/合计；相同配置合并数量。种子门店当前为未营业状态，可预选门店和保存购物车。

第六阶段新增切片：已实现服务端重新校验购物车商品和规格并计价、事务创建待支付订单、扣减商品与加料库存、订单快照、用户订单列表/详情以及未支付订单取消和库存一次性回补。用户端购物车现可在营业门店提交订单，“我的订单”可查看订单并取消未支付订单。支付服务未接入，页面明确提示不可支付。已有数据库必须先执行 `database/migrations/2026-09-25-order-stock-reservation.sql`，再使用下单/取消接口；种子门店为 CLOSED 状态时不能提交订单。

每个阶段应形成完整模块并检查后再推进。不要用假 API 或假数据冒充已连通的服务。

## 本地检查

```powershell
cd d-coffee-front; npm run build:h5
cd ..\d-coffee-admin; npm run build
cd ..\d-coffee-backend; .\mvnw.cmd test
```

后端需要 JDK 17。前端本地环境变量放在 Git 忽略的 `.env.local` 文件中。不要提交数据库密码、JWT 签名密钥或服务商凭据。

两端开发服务器默认将 `/api` 代理到 `http://localhost:8080/d_coffee_backend_war_exploded`。复制各自的 `.env.example` 为 `.env.local`，Tomcat 上下文不同则修改 `VITE_API_CONTEXT`。部署到其他地址时设置 `VITE_API_BASE_URL`；微信小程序需要可访问的完整 API 地址。
